  • 기존,신규 시스템의 DB 및 프로그램 로직 비교 분석
  • 영향도와 Migration 범위 산정, 구현 방안 수립
  • DB별 마이그레이션 로직 구현 및 피드백 반영
  • 사용자 교육, 시스템 오픈 및 안정화 지원
기존 방식을 그대로 적용하지 않고 시스템 차이를 분석해 DB별 맞춤형 Migration 방안을 구현
시행착오를 극복한 사례
기존 Excel 기반 Migration의 한계를 분석하고 DB별 전환 로직으로 해결
1. 어려움 및 문제 상황약 3년간 누적된 데이터와 기존,신규 시스템의 DB 구조 및 프로그램 로직이 달라, 기존 Excel 기반 Migration 방식을 그대로 적용하기 어려웠습니다.
2. 원인 분석기존,신규 시스템의 DB 구조와 프로그램 로직을 비교 분석하고, 데이터 차이에 따른 영향도와 Migration 대상 범위를 검토했습니다.
3. 극복을 위한 실행영향도와 Migration 범위를 산정한 뒤 DB별 특성에 맞는 전환 로직을 구현했습니다. 검토 과정에서 받은 피드백을 반영해 전환 방안을 보완했습니다.
4. 결과 및 배운 점DB별 특성을 반영한 Migration 방안을 적용해 시스템 오픈과 안정화를 지원했습니다. 이 경험을 통해 기존 방식의 한계를 인정하고, 원인을 분석해 시스템 구조에 맞는 대안을 구현하는 문제 해결 과정을 익혔습니다.
문제 상황 파악 → DB,로직 비교 분석 → DB별 Migration 구현 → 시스템 오픈 및 안정화 지원
